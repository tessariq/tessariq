# Skills Overview

Skill catalog for deterministic tracked-work execution in Tessariq.

Every skill is **vendored**: a byte-exact copy of the skill package embedded in the taskrail release
pinned in `mise.toml`. None of them is authored here.

## Vendored Skills

Tracked-work execution:

- `autonomous-backlog`
- `autonomous-manual-test`
- `autonomous-recovery`
- `autonomous-task`
- `autonomous-verify`

Spec and backlog authoring:

- `taskrail-decompose`
- `taskrail-gap`
- `taskrail-import`
- `taskrail-repair`
- `taskrail-retrofit`
- `taskrail-spec`

## Packaging

- Mirrored skill files live in `.agents/skills/` and `.claude/skills/` and must stay byte-identical.
- `docs/workflow/skills-manifest.yml` records the pinned taskrail version and a SHA-256 per skill. It
  is generated by `scripts/vendor-skills.sh`; never edit it by hand.
- `task workflow:check-skills` enforces mirror parity, the manifest digests, the manifest-to-`mise.toml`
  version match, the absence of version markers and backup siblings, and frontmatter-to-directory
  name agreement. It runs in both CI lanes and on pre-commit.
- Canonical workflow guidance lives in `docs/workflow/`, not in the skills.

## Never Hand-Edit A Skill

An edit to a vendored skill is lost at the next re-vendor and fails `task workflow:check-skills` in
the meantime. If a skill needs to behave differently here, change the upstream taskrail package, or
record the repository-specific rule in `docs/workflow/` and `AGENTS.md` instead.

## Re-vendoring

```sh
task workflow:skills:vendor
```

This copies the embedded skill package out of the Go module cache for the pinned version and
regenerates the manifest. Bumping the taskrail pin in `mise.toml` without re-vendoring fails
`task workflow:check-skills`, so the two cannot drift.

**Never run `taskrail init --with-skills --force` in this repository.** It stamps a `taskrail_version`
marker derived from the running binary — `0.0.0-dev` for any `go install` build, which is what the
mise backend produces — and taskrail only exempts a skill from version-skew warnings when it is
unstamped *and* byte-identical to the package the running binary embeds. `--force` also writes
`SKILL.md.bak.<timestamp>` siblings into both trees, which mirror parity cannot detect because they
land in both symmetrically.

## Where Repository-Specific Rules Live

The vendored skills are repo-agnostic: they contain no reference to `AGENTS.md`, `CLAUDE.md`, or
`docs/workflow/`. Tessariq's own mandates — the testing pyramid, the Testcontainers-for-Go
requirement, container and bind-mount permission rules, the nightly mutation gate, one
conventional-commit per task, and the manual-test artifact templates — live in `AGENTS.md` and
`docs/workflow/`, and are loaded by the harness rather than by the skills.

## History

The skill trees previously mixed vendored copies with five locally forked skills squatting upstream
names, plus a local-only `autonomous-verify-hybrid`. Because `taskrail init --with-skills` never
overwrites an existing file, the forks were silently skipped at install time and then diverged. They
have been replaced by the upstream originals; `autonomous-verify-hybrid` was removed and its
deterministic-low-risk-fix rule now lives in `docs/workflow/autonomous-contract.md`.

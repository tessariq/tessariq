## Summary

Three preflight failures that occur before any container starts have no e2e coverage: missing Claude Code credentials, missing OpenCode `auth.json`, and an unrecognized `--model provider/model` prefix under `--egress auto`.

## Motivation

These are the first errors a misconfigured user hits, and the spec's Failure UX section requires each to name the problem and the fix rather than surfacing a raw I/O error. BUG-010 was exactly this class of defect for OpenCode. They cost nothing to test because the agent never starts.

## Acceptance Criteria

- An e2e case runs Claude Code with the credentials file absent and asserts the run fails before agent start, telling the user to authenticate Claude Code locally.
- An e2e case runs OpenCode with `auth.json` absent and asserts an actionable auth-missing message, explicitly not a raw filesystem error (BUG-010 regression).
- An e2e case passes `--agent opencode --model notaprovider/x --egress auto` and asserts the failure names the unrecognized provider prefix and suggests `--egress-allow` or `--egress open`.
- All three assert a non-zero exit and that no container was created.

## Test Expectations

- Build tag `//go:build e2e`; new cases live alongside the existing suite in `cmd/tessariq/`.
- Use `containers.StartRunEnv` and the default `runTessariq` helper (which passes `--no-update-agent`); add a `Start*` helper to `internal/testutil/containers/` if a new collaborator is genuinely required.
- No host-tool guards and no local fake binaries or servers: the container supplies every runtime dependency.
- Runs on GitHub Actions `ubuntu-latest` in the existing `e2e` CI job with no secrets, no credentials, and no billed model calls.

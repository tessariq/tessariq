## Summary

No e2e case proves that a run which writes a binary file produces a `diff.patch` containing that change and promotes successfully.

## Motivation

BUG-033 was `git diff` being invoked without `--binary`, so binary additions and modifications were silently dropped from the patch and lost at promote. The user saw a successful run and a commit that was missing their file. Unit coverage of the flag does not prove the artifact round-trips through promote.

## Acceptance Criteria

- An e2e case runs a fake agent that writes a binary file and asserts `diff.patch` contains the binary change (BUG-033 regression).
- The case asserts `diffstat.txt` reflects the change.
- The case promotes the run and asserts the resulting commit contains the binary file with its content intact.

## Test Expectations

- Build tag `//go:build e2e`; new cases live alongside the existing suite in `cmd/tessariq/`.
- Use `containers.StartRunEnv` and the default `runTessariq` helper (which passes `--no-update-agent`); add a `Start*` helper to `internal/testutil/containers/` if a new collaborator is genuinely required.
- No host-tool guards and no local fake binaries or servers: the container supplies every runtime dependency.
- Runs on GitHub Actions `ubuntu-latest` in the existing `e2e` CI job with no secrets, no credentials, and no billed model calls.

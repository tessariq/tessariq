## Summary

Hook coverage is limited to the pre-hook timeout path. Two behaviors are uncovered: hooks executing with the repository root as working directory, and the run outcome when a `--verify` hook fails.

## Motivation

T-072 fixed hooks running with the evidence directory as CWD, which broke every relative-path project command such as `go test ./...` and forced an inline `cd` workaround. Nothing asserts the fixed behavior, so it can regress back into a confusing failure mode.

## Acceptance Criteria

- An e2e case passes `--pre` and `--verify` commands that assert their working directory is the repository root, not the evidence directory (T-072 regression).
- The case asserts hook output is captured in `runner.log`.
- An e2e case with a failing `--verify` hook asserts the run outcome reflects the failure and the CLI exits non-zero.
- An e2e case asserts a relative-path command such as `ls <repo-relative-file>` succeeds inside a hook without an inline `cd`.

## Test Expectations

- Build tag `//go:build e2e`; new cases live alongside the existing suite in `cmd/tessariq/`.
- Use `containers.StartRunEnv` and the default `runTessariq` helper (which passes `--no-update-agent`); add a `Start*` helper to `internal/testutil/containers/` if a new collaborator is genuinely required.
- No host-tool guards and no local fake binaries or servers: the container supplies every runtime dependency.
- Runs on GitHub Actions `ubuntu-latest` in the existing `e2e` CI job with no secrets, no credentials, and no billed model calls.

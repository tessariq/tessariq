## Summary

No e2e case interrupts a run in progress. The manual plan requires that a `Ctrl-C` on `tessariq run` cleans up the worktree, the agent container, the Squid container, and the per-run network, and that the recorded terminal status agrees with the CLI exit code.

## Motivation

BUG-048 was this defect: interrupted runs were left indefinitely `running` with leaked resources. The fix shipped, but interrupt handling is the single most leak-prone path in the lifecycle and has no automated coverage at all. Leaks here accumulate silently on a user's machine.

## Acceptance Criteria

- An e2e case starts a run in proxy mode, sends SIGINT to the CLI process mid-run, and asserts a non-zero exit.
- The case asserts no leftover agent container, no leftover Squid container, and no leftover per-run Docker network.
- The case asserts the worktree is removed and `git worktree list` has no stale entry.
- The case asserts `status.json` records a terminal, non-`running` state consistent with the CLI exit code (BUG-048 regression).
- The case asserts terminal evidence was written before container removal.

## Test Expectations

- Build tag `//go:build e2e`; new cases live alongside the existing suite in `cmd/tessariq/`.
- Use `containers.StartRunEnv` and the default `runTessariq` helper (which passes `--no-update-agent`); add a `Start*` helper to `internal/testutil/containers/` if a new collaborator is genuinely required.
- No host-tool guards and no local fake binaries or servers: the container supplies every runtime dependency.
- Runs on GitHub Actions `ubuntu-latest` in the existing `e2e` CI job with no secrets, no credentials, and no billed model calls.

## Summary

`promote` already has e2e coverage for tampered manifests, tampered egress mode, and forged evidence paths, but not for evidence that is simply missing or structurally incomplete: a deleted `status.json`, or an `agent.json` that is non-empty yet malformed (`{`) or well-formed but incomplete (`{"x":1}`).

## Motivation

BUG-063 was precisely this: non-empty but malformed evidence passed the completeness check silently, so promote proceeded on unproven runs. The fix shipped in T-099 and is covered by unit tests, but no e2e case proves the gate holds end to end before Git is touched.

## Acceptance Criteria

- An e2e case deletes `status.json` from a finished run and asserts promote fails naming the missing artifact, with no branch and no commit created.
- An e2e case overwrites `agent.json` with `{` and asserts rejection as malformed evidence.
- An e2e case overwrites `agent.json` with `{"x":1}` and asserts rejection as incomplete evidence (BUG-063 regression).
- Every case asserts the repository is unchanged: no new branch, no new commit, `git status` clean.

## Test Expectations

- Build tag `//go:build e2e`; new cases live alongside the existing suite in `cmd/tessariq/`.
- Use `containers.StartRunEnv` and the default `runTessariq` helper (which passes `--no-update-agent`); add a `Start*` helper to `internal/testutil/containers/` if a new collaborator is genuinely required.
- No host-tool guards and no local fake binaries or servers: the container supplies every runtime dependency.
- Runs on GitHub Actions `ubuntu-latest` in the existing `e2e` CI job with no secrets, no credentials, and no billed model calls.

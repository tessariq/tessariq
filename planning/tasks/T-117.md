## Summary

Most of the v0.1.0 manual test plan is automatable, but a residue is not. Record which cases remain human-only, why, and how they are signed off, so the distinction is deliberate rather than forgotten.

## Motivation

`docs/release-readiness-v0.1.0.md` is an untracked working file pinned to one commit and one release. Once the automatable cases land as e2e tests, the remaining human cases need a durable home, or the next release will either repeat the whole manual plan from scratch or quietly skip it.

## Acceptance Criteria

- A short document (suggested `docs/release-verification.md`) lists the cases that cannot be automated and states the reason for each:
  - real-agent output quality and PTY readability under `attach` and `run --attach` (manual plan T1.3, T1.7)
  - interactive approval with a human present (T2.9)
  - confirming the agent actually consumes a mounted config signal (T2.3)
  - real-provider runs against Claude Code and OpenCode with live credentials and billed model calls (T1.2, T2.1, T2.5, T2.6)
  - OpenCode dual-host provider resolution needing real provider config (T3.2)
  - macOS-only behavior: Keychain-only credentials (T4.10) and VirtioFS bind-mount UID mapping (manual plan section 5)
- The document states which platforms each residual case must run on, and that darwin cases require Apple hardware because macOS cannot be containerized or legally virtualized on other hardware.
- The document is referenced from the release checklist so it is consulted per release rather than rediscovered.
- Cases automated by T-107 through T-116 are explicitly listed as no longer requiring a human pass.


## TDD Plan

- Documentation task; no test loop. Validate by walking the manual plan case list and confirming every case is either automated by T-107 through T-116 or recorded here with a reason.

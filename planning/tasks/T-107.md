## Summary

The v0.1.0 manual plan checks that `tessariq init` creates `.tessariq/` and `.tessariq/runs/` at mode `0700`, appends the `.tessariq/` entry to `.gitignore`, and is idempotent on a second invocation. No e2e case asserts any of this; the only init-related e2e test covers the missing-`git` failure path.

## Motivation

Init is the first command a new user runs, and its permission contract is a security boundary: `0700` on the runs tree is what keeps other host users from enumerating live run IDs. A regression to `0755` would be invisible to every existing test.

## Acceptance Criteria

- An e2e case asserts `.tessariq` and `.tessariq/runs` are both created with mode `0700`.
- An e2e case asserts `.gitignore` gains a `.tessariq/` entry, and that a repository already containing the entry is not given a duplicate.
- An e2e case asserts a second `tessariq init` succeeds, changes nothing, and tightens permissions when an existing directory is more permissive than `0700`.

## Test Expectations

- Build tag `//go:build e2e`; new cases live alongside the existing suite in `cmd/tessariq/`.
- Use `containers.StartRunEnv` and the default `runTessariq` helper (which passes `--no-update-agent`); add a `Start*` helper to `internal/testutil/containers/` if a new collaborator is genuinely required.
- No host-tool guards and no local fake binaries or servers: the container supplies every runtime dependency.
- Runs on GitHub Actions `ubuntu-latest` in the existing `e2e` CI job with no secrets, no credentials, and no billed model calls.

# T-119 Vendor taskrail skills verbatim and bump to v0.4.0

## Description

The mirrored agent skill trees are in a provenance limbo. `taskrail init --with-skills` never
overwrites existing files, so the initial adoption installed only the four non-colliding
`taskrail-*` skills and silently skipped the five `autonomous-*` names this repository already
owned. Those five were then hand-patched into permanent forks, and nothing on disk marks which
files are vendored and which are local.

The forks also lost upstream detail: the `${TASKRAIL:-taskrail}` binary indirection, the
PATH preamble, and — most importantly — `autonomous-recovery` dropped the dry-run-first step and
jumps straight to `taskrail repair --apply`, contradicting the vendored `taskrail-repair` skill
beside it.

taskrail v0.4.0 stamps `taskrail_version` into installed skill frontmatter and warns on skew.
Files that are both unmarked and diverged from the embedded package — exactly the five forks —
produce a warning upstream deliberately gives no remedy for, so it can never be cleared while the
names collide.

Resolution: adopt taskrail's skills verbatim. Delete every local skill, bump the pin to v0.4.0,
reinstall all eleven upstream skills into both trees, and add a guard so the drift cannot recur.
Repository-specific mandates that only lived inside the forked skills move into `docs/workflow/`
and `AGENTS.md` first, so nothing is lost.

## Acceptance

- `.agents/skills/` and `.claude/skills/` each contain exactly the eleven skills embedded in
  taskrail v0.4.0, byte-identical between the two trees.
- No local or forked skill remains; `autonomous-verify-hybrid` is removed and its
  deterministic-low-risk-fix rule is recorded in `docs/workflow/autonomous-contract.md`.
- Every `SKILL.md` is an unstamped, byte-exact copy of the embedded skill package, and
  `docs/workflow/skills-manifest.yml` records the pinned version plus a SHA-256 per skill.
  (Revised during implementation: the original criterion required a `taskrail_version` marker
  equal to the pin. That is unachievable — the version is a GoReleaser ldflag that `go install`
  never sets, so the marker would read `0.0.0-dev` — and harmful, because taskrail exempts a skill
  from skew warnings only when it is unstamped and byte-identical to the package. See MT-003.)
- `mise.toml` pins taskrail `0.4.0`, and the `AGENTS.md` fallback install line matches.
- No `*.bak.*` file exists under either skill tree.
- `task workflow:check-skills` fails on a hand-edited skill, on a pin/marker mismatch, and on a
  committed `.bak` sibling, and runs in both the code and planning CI lanes without editing either
  workflow's path list.
- The manual-test plan/report templates previously carried only by the forked
  `autonomous-manual-test` skill are preserved in `docs/workflow/development-workflow.md`.
- `docs/workflow/skills-overview.md` lists all eleven skills, marks them vendored, and documents the
  re-vendor procedure plus the prohibition on `taskrail init --with-skills --force`.

## Verification Notes

- Manual test plan and report exist locally in this task's gitignored manual-test artifact
  directory, alongside the verify report.
- Nine manual test steps, verdict pass-with-fixes: 8 pass, 1 fixed (MT-003, the vendoring-method
  correction described above).
- Guard negative-tested on all four drift modes; the `.bak`-sibling case confirms `diff -rq` alone
  cannot detect symmetric backup litter.
- Skew payoff measured in one scratch repository with a release-versioned v0.4.0 binary: the five
  pre-change forks emit an unclearable unknown-version warning, the vendored trees emit nothing.

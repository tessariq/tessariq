# T-118 Align release-readiness T3.6 with the enforced open+allowlist rejection

## Description

docs/release-readiness-v0.1.0.md T3.6 says combining --egress open with --egress-allow must 'produce a warning that the allowlist is ignored'. The implementation instead rejects it at validation (internal/run/config.go:77-79: 'egress-allow cannot be used with egress mode open; allowlists require proxy mode'), which is fail-closed and is what T-111 criterion 4 and TestE2E_EgressOpenWithAllowRejected assert. The manual plan text is stale and would make a human tester report a false failure. Decide whether the doc should be corrected to describe the rejection, or whether the spec intends warning-and-ignore instead; specs/tessariq-v0.1.0.md#networking-and-egress is normative.

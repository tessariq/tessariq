## Summary

Proxy mode has e2e coverage for writing egress evidence and for requiring it at promote, but not for the two user-visible behaviors: the blocked-destination message when Squid denies a host, and the promotability of an honest run where nothing was blocked.

## Motivation

BUG-064 made zero-denied proxy runs unpromotable because they emitted a 0-byte `egress.events.jsonl`. T-100 fixed it with an explicit zero-events representation. Without an e2e case, the next change to telemetry extraction can silently reintroduce a file that is indistinguishable from a truncated write.

## Acceptance Criteria

- An e2e case runs a fake agent that requests a destination outside the allowlist and asserts the request is blocked, `egress.events.jsonl` records the denied `host:port` with a reason, and the CLI guidance names how to allow it.
- A follow-up case adds the destination via `--egress-allow` and asserts it then succeeds.
- An e2e case runs proxy mode with every needed destination already allowed and asserts `egress.events.jsonl` is non-empty and parseable as an explicit zero-events summary, not a 0-byte file (BUG-064 regression).
- The zero-denied run is asserted to be promotable.

## Test Expectations

- Build tag `//go:build e2e`; new cases live alongside the existing suite in `cmd/tessariq/`.
- Use `containers.StartRunEnv` and the default `runTessariq` helper (which passes `--no-update-agent`); add a `Start*` helper to `internal/testutil/containers/` if a new collaborator is genuinely required.
- No host-tool guards and no local fake binaries or servers: the container supplies every runtime dependency.
- Runs on GitHub Actions `ubuntu-latest` in the existing `e2e` CI job with no secrets, no credentials, and no billed model calls.

## Summary

Cleanup is covered for the failure path (`TestE2E_FailedRunCleansUpWorktree`) but not for a successful run. The manual plan sweeps for leftover containers, leftover networks, a removed worktree, no stale `git worktree` entries, and a removed per-run runtime-state directory.

## Motivation

Success-path leaks are the worst kind: nothing looks wrong, and the user accumulates containers, networks, worktrees, and copied credentials under `~/.tessariq/runtime-state/` over time. The runtime-state directory holds a copy of host auth, so failing to remove it is also a security concern.

## Acceptance Criteria

- An e2e case completes a successful run and asserts no container matching `tessariq-<run_id>` remains.
- The case asserts no per-run Docker network remains.
- The case asserts the worktree directory is gone and `git worktree list` has no stale entry.
- The case asserts the per-run directory under `~/.tessariq/runtime-state/` is removed, including the copied auth file.
- The same sweep is asserted after a timed-out run, so cleanup is proven on more than the happy path.

## Test Expectations

- Build tag `//go:build e2e`; new cases live alongside the existing suite in `cmd/tessariq/`.
- Use `containers.StartRunEnv` and the default `runTessariq` helper (which passes `--no-update-agent`); add a `Start*` helper to `internal/testutil/containers/` if a new collaborator is genuinely required.
- No host-tool guards and no local fake binaries or servers: the container supplies every runtime dependency.
- Runs on GitHub Actions `ubuntu-latest` in the existing `e2e` CI job with no secrets, no credentials, and no billed model calls.
